1　這是什麼、為什麼這樣做

CodeAtlas 是一個給 C# 專案用的程式碼語意分析工具。「語意」的意思是:它不是把程式碼當文字搜尋,而是像編譯器一樣讀懂它——知道某個名字指的是哪個類別、哪個方法,誰呼叫了誰,哪個欄位被讀、哪個被寫。

它的目標情境很具體:公司的大型 .NET Framework 4.8 專案,電腦完全離線、不能安裝任何東西,只保證有 .NET 4.8、Visual Studio 和 Copilot。在這個限制下,CodeAtlas 做到:

  • 符號瀏覽、找參考(分開讀與寫)、呼叫階層、多層影響分析;
  • 品質度量、死碼、循環相依、重複程式碼、God Class 解剖、冤親債主;
  • 類別圖、關係圖、函式流程圖(循序圖、活動圖、狀態圖、資料流)與可手動整理的流程畫布;
  • 產生給 Copilot 的「AI 上下文」——短、準、只給簽章,需要時再讀指定函式的內文。

1.1　為什麼不直接內嵌 Serena

一開始的想法是把 Serena(一套讓 AI 具備「像 IDE 一樣看懂程式碼」能力的開源工具)放進來。評估後決議不內嵌,改用 Roslyn 直接在 net48 上跑。原因在第 9.3 節有逐點說明,這裡先給結論:Serena 需要先安裝 uv 與 Python 環境、處理 C# 時需要 .NET 10 以上的執行環境、語言伺服器在首次使用時需要下載——這三件事都和「離線、不能安裝、只有 .NET 4.8」直接衝突。

所以 CodeAtlas 的做法是:用 Roslyn(微軟的 C# 編譯器平台)的程式介面,自己實作 Serena 背後那一層「語言伺服器」做的事,並把結果整理成人看得懂的網頁與 AI 看得懂的短文字。

這份文件怎麼讀 第 2、3 章讓你把工具跑起來;第 4~8 章是功能;第 9 章專談和 Copilot 搭配;附錄 B 是各知識點的延伸書單(書名、作者、出版資訊都已上網查證,查證紀錄也列在那裡)。每個功能都附實際執行的畫面或輸出,輸出都來自隨附的測試專案,不是編造的。

2　安裝與啟動(離線)

2.1　需要什麼

  • Windows,已有 .NET Framework 4.8(Windows 10 以後通常已內建);
  • 任何現代瀏覽器(Edge、Chrome 皆可),用來看網頁介面;
  • 要用「冤親債主」功能時,需要 git(CodeAtlas 會依序找:PATH、Git for Windows 安裝位置、Visual Studio 內附的 git)。

不需要:網路、系統管理員權限、安裝程式、Python、Java、Node。

2.2　只拿 Release 去別的電腦用

可以。整個發佈資料夾(CodeAtlas)就是一份完整的免安裝版,包含:

samples\本文所有範例用的自建測試專案。
本說明 PDF

這個免安裝版已實際用「解壓縮到另一個資料夾再執行」的方式測試過(見附錄 D)。

2.3　啟動,以及從網頁開啟專案

最簡單:直接雙擊 CodeAtlas.exe。會出現一個黑色視窗(請保持開著),並自動開啟瀏覽器的「開啟專案」頁,你在那裡輸入或挑選專案路徑即可,不必用命令列。要結束時關掉黑色視窗(或在視窗按 Ctrl+C)。

其他啟動方式(結果相同):

  • 把 .sln 或 .csproj 拖到 CodeAtlas.exe 或 啟動 CodeAtlas.bat 上:直接載入該專案並開啟總覽;
  • 命令列 CodeAtlas.exe serve:和雙擊一樣,先開「開啟專案」頁;
  • 命令列 CodeAtlas.exe serve 你的方案.sln 5173 --open:直接載入指定專案(埠號預設 5173,被占用時會自動往後找一個)。

伺服器只聽本機(localhost),不對外開放,也不需要系統管理員權限。

2.3.1　「開啟專案」頁

  • 輸入路徑:填 .sln 或 .csproj 的完整路徑,按「開啟」或 Enter。可以直接貼上含引號的路徑(檔案總管「複製為路徑」的結果)。
  • 輸入資料夾也可以:程式會在資料夾裡(含下三層,略過 bin、obj、.git 等)找 .sln 或 .csproj。找到一個就直接開,找到多個會列出來讓你選。
  • 瀏覽資料夾(右下):瀏覽器拿不到檔案的完整路徑,所以由本機程式幫你列出。點資料夾往下進、點「上一層」往上、點上方麵包屑跳回;點一個 .sln 或 .csproj 會填入路徑,點兩下直接開啟。左邊有桌面、文件、使用者資料夾的捷徑。
  • 最近開啟(左下):記住最近 12 個專案(連同「用原始碼取代 DLL」的設定),點一下就重新開啟;✕ 可從清單移除。紀錄存在 %AppData%\CodeAtlas\recent.json。
  • 進階:用原始碼取代 DLL:每行一個「DLL名稱=原始碼位置」,等同第 3.2 節的 --source;方案旁的 codeatlas.sources 也會自動套用。

按下「開啟」後,頁面會顯示載入進度(讀取、建立語意模型、分析類別關係…),完成後自動前往總覽。大型專案載入需要一點時間,這段時間可以繼續使用瀏覽器,不會卡住。

切換專案每一頁頂端導覽列都有「📂 專案名稱」,點它就回到這一頁,可以隨時換成別的專案;換專案時舊的分析結果會整組換掉。載入失敗時(例如專案檔壞了),原本開著的專案會保留,頁面會顯示失敗原因。載入進行中不能同時開第二個專案。

2.3.2　網頁導覽

網頁的頂端有固定的導覽列,最左邊是 🏠 總覽,按了就回到首頁。

3　載入專案,以及用原始碼取代 DLL

3.1　載入方式

所有指令的第二個參數都是 .sln 或 .csproj。CodeAtlas 不依賴 MSBuild 或 Visual Studio 是否已開啟:它自己讀專案檔,找出要編譯的 .cs 檔與參考的 DLL,交給 Roslyn。

  • 舊式與 SDK 風格的 .csproj 都支援;
  • 專案間的參照(ProjectReference)會建立成真正的跨專案語意,所以影響分析可以跨專案追;
  • Reference 的 HintPath 與 SDK 風格的 PackageReference(從本機 .nuget\packages 快取找 DLL)都會處理,找不到會警告;
  • .NET Framework 的核心組件(mscorlib、System、System.Windows.Forms 等)直接取用執行環境裡的那份。
CodeAtlas.exe symbols samples\TestShop.sln
{{snip:symbols}}

3.2　選擇性加入 DLL 的原始碼,取代掉 DLL

你的專案可能參照了公司內部的 DLL,而你手上剛好有那份 DLL 的原始碼。只靠 DLL,CodeAtlas 看得到它的型別簽章,但看不到內部、也追不進去。加上 --source,就會用原始碼取代那個 DLL 參照,分析就能穿過去。

CodeAtlas.exe refs samples\DllDemo\DllDemo.sln Greeter.Hello
CodeAtlas.exe refs samples\DllDemo\DllDemo.sln Greeter.Hello --source Lib=samples\DllDemo\Lib\Lib.csproj

沒有 --source(App 專案只參照 Lib.dll):

{{snip:source-without}}

加上 --source Lib=…\Lib.csproj:

{{snip:source-with}}
  • --source DLL名稱=位置:DLL 名稱不含 .dll;位置可以是 .csproj,也可以是一個資料夾(會取裡面所有 .cs,略過 bin、obj);可重複指定多個。
  • 也可以在方案旁放一個 codeatlas.sources 文字檔,每行一個 DLL名稱=位置,以 # 開頭是註解。這樣每次不用打參數。
  • 若指定的 DLL 沒有被任何專案參照,會提示並略過。
注意被取代的原始碼若再依賴別的 DLL,也可以一併用 --source 取代;沒取代的就仍以 DLL 形式參照。原始碼與 DLL 的版本不一致時,分析的是「你手上的原始碼」,不是實際執行的 DLL。

4　找符號、找參考、呼叫階層、影響分析

名稱可以寫短的(Order、Order.ApplyDiscount),也可以寫完整顯示名稱。名稱不唯一時,CodeAtlas 會列出候選,不會亂猜。

4.1　尋找符號 find

CodeAtlas.exe find samples\TestShop.sln Order
{{snip:find}}

4.2　找參考,分開讀與寫 refs

每一處使用都會分類:讀、寫、讀寫(+=、++、ref 參數)、呼叫、建立物件、型別使用、方法群組參照(把方法當委派傳)。

CodeAtlas.exe refs samples\TestShop.sln Order.Total
{{snip:refs}}

注意 Total += … 判為「讀寫」、Total = … 判為「寫」、return Total 判為「讀」。

4.3　呼叫階層 calls

同時給兩個方向:誰呼叫它(被呼叫),以及它呼叫誰。可指定層數,遇到循環會標示 [循環]。

CodeAtlas.exe calls samples\TestShop.sln Checkout.Run 2
{{snip:calls}}

4.4　多層影響分析 impact

「我改了這個,會牽動誰?」往上一層一層追所有直接與間接使用者,每個成員只出現一次。透過介面與覆寫的呼叫也會連回實作(例如 OrderService.Create 是被當成 IOrderService 呼叫的,仍然追得到)。

CodeAtlas.exe impact samples\TestShop.sln Customer.DiscountRate
{{snip:impact}}
它追不到什麼影響分析追的是「呼叫與使用」這種靜態關係。反射、依賴注入容器、事件訂閱的字串名稱、設定檔裡的類別名稱都追不到。重大修改前,請把它當成「至少會影響這些」,不是「只會影響這些」。
延伸閱讀 想在不熟的大型程式裡安全地改動,可看 Michael Feathers《Working Effectively with Legacy Code》(Prentice Hall,2004;ISBN 9780131177055)。書中談如何把遺留程式碼放進測試、以及一套打破相依性的手法。(附錄 B)

6　程式碼品質分析

本章六個項目都用隨附的測試專案示範。所有「推測」性質的結果都會在該節標明,請當作線索,不要當作判決。

6.1　品質度量

指令:metrics [N];網頁:首頁的表格,以及類別圖頁右側的符號資訊欄。

縮寫名稱意思怎麼算
CC循環複雜度程式裡有多少條獨立的執行路徑。越高越難測、越容易出錯。1 + if、while、for、foreach、每個 case、catch、?:、&&、||、?? 的個數
巢狀最大巢狀深度最深的 if/for/while/switch/try 層數。else if 不算多一層。—
MI維護性指數 0~100越高越好維護。171 − 5.2·ln(V) − 0.23·CC − 16.2·ln(LOC),再換算成 0~100
WMC加權方法數一個類別裡所有方法 CC 的總和,反映類別整體的複雜度。Σ CC
Ca傳入耦合有多少其他類別用到它(被依賴的程度)。不重複的使用者類別數
Ce傳出耦合它用到多少其他類別(依賴別人的程度)。不重複的被使用類別數
CodeAtlas.exe metrics samples\TestShop.sln 4
{{snip:metrics}}

實際核對:Pricing.Score 裡有 if、&&、for、兩個 case、一個 ?:,手算 CC = 1+1+1+1+2+1 = 7,工具也是 7;for 在 if 裡,巢狀 2。

MI 是近似值標準公式裡的 Halstead 體積 V,CodeAtlas 是用語法標記估算的(識別字與字面值當運算元,其餘當運算子),所以數字會和 Visual Studio 內建的不同。拿來比較「同一份程式裡誰比較差」可以,拿來和別的工具的數字互比不行。
延伸閱讀 ・循環複雜度的原始論文:Thomas J. McCabe, “A Complexity Measure”, IEEE Transactions on Software Engineering, SE-2(4), 1976, pp. 308–320。
・WMC、耦合等物件導向度量出自 Shyam Chidamber 與 Chris Kemerer 的研究。我查證到的是 MIT 的工作論文 “Towards a Metrics Suite for Object Oriented Design”(1991)與修訂版 “A metrics suite for object oriented design (revised)”(1993);正式期刊版本我沒能在網路上確認,所以不在此列出頁碼。(附錄 B)

6.2　死碼偵測

指令:dead;網頁:首頁的「死碼」表。找出「方案裡沒有任何人使用」的成員與型別,並分可信度:

可信度條件為什麼
高私有,且整個方案都沒有參照私有成員只有自己的類別看得到,沒人用就是沒人用。
中內部(internal)且沒有參照;或私有欄位「只被寫入、從未被讀取」內部成員仍可能被「友人組件」使用。
低公開成員,方案內沒有參照可能被方案外的程式、反射或序列化使用。

有屬性標註([…])、或名稱像事件處理常式(btn_Click)的,會再降一級,因為框架或反射可能呼叫它。覆寫、介面實作、Main、列舉成員、抽象成員不列入。

CodeAtlas.exe dead samples\TestShop.sln
{{snip:dead}}
延伸閱讀 刪死碼之前通常要先有測試的保護。Feathers《Working Effectively with Legacy Code》談的就是沒有測試時怎麼動手;Martin Fowler《Refactoring》第 2 版(Addison-Wesley,2018)收錄一整套小步驟、可逆的重構手法。(附錄 B)

6.3　循環相依

指令:cycles。找出互相依賴的群組,分專案、命名空間、型別三層。用「強連通元件」演算法,只列出大小超過 1 的群組(自己依賴自己不算)。

CodeAtlas.exe cycles samples\TestShop.sln
{{snip:cycles}}

型別層級的小循環(例如兩個類別互相持有)很常見,未必是問題;專案與命名空間層級的循環才是結構性的警訊,因為它讓這些單位無法獨立編譯、測試或發佈。

延伸閱讀 Robert C. Martin《Clean Architecture》(Pearson,2017)第 14 章「Component Coupling」談無循環相依原則、穩定相依原則與穩定抽象原則——這正是 Ca、Ce 與「不穩定度 = Ce / (Ca + Ce)」背後的想法。(附錄 B)

6.4　重複程式碼偵測

指令:clones [標記數] [最少行數];網頁:/clones。它把每個方法轉成「語法標記」序列,用固定長度的視窗比對,連續命中的視窗合併成一段。預設會把變數名稱與常數視為相同,所以「複製貼上後改了名字」的重複也抓得到;勾選「只找完全相同」則要求一字不差。

CodeAtlas.exe clones samples\GodDemo\GodDemo.sln 40 6
{{snip:clones}}
  • 比對長度越小越敏感,但雜訊越多;預設 40 個標記、至少 6 行。
  • 預設略過 .Designer.cs 等自動產生的檔案(那裡面本來就是大量相似的程式),可勾選納入。
  • 一長串完全相同的樣板(同一視窗出現 40 次以上)會被當作樣板略過。
它找得到與找不到找得到:結構相同、只有名稱或常數不同的複製貼上。找不到:邏輯相同但寫法不同(例如一個用 for、一個用 LINQ)的「語意重複」。
延伸閱讀 David Thomas、Andrew Hunt《The Pragmatic Programmer》20 週年紀念版(Addison-Wesley,2019),Topic 9「DRY—The Evils of Duplication」。作者後來表示 DRY 原本談的是「知識」不要重複,而不只是「別複製貼上」。(附錄 B)

6.5　God Class 解剖

網頁:/god。針對一個過大的類別(例如你那個約 6 萬行的畫面類別),拆成四張表。左側清單依行數排序,選一個類別即可。下面用隨附的 GodDemo(一個迷你的 WinForms 畫面類別)示範。

(1)欄位清冊

每個欄位與屬性:被幾個成員讀、被幾個成員寫、類別內與外部各用了幾次,並標旗標:未使用、只寫不讀、只被一個成員使用(可能其實該是區域變數)、樞紐(被超過門檻比例的成員共用)。

(2)職責分群

把方法依「共用的欄位」與「互相呼叫」綁成群;每一群是一個可能獨立出去的職責。被太多成員共用的欄位或方法(例如寫記錄的 Log)視為「樞紐」,不拿來綁群,否則所有方法會被它綁成一大團。頁面上方的「樞紐門檻」滑桿可以調整。另外算出 LCOM4(分成幾個互不相連的群),越大表示這個類別做了越多件不相干的事。

(3)儲存對照

推測哪些欄位對應到「儲存」(設定檔、資料庫、序列化),依三種線索:屬性標註(如 [XmlElement]、[DataMember])、字串鍵(ini.Write("Exposure", _exposure…)、_gain = … ini.Read("Gain")、row["欄位名"])、同名字串。

(4)UI 對照

列出控制項(WinForms 的 Control、ToolStripItem,WPF 的 UIElement),它們的事件掛接(btnSave.Click += …btnSave_Click)、被哪些成員使用,以及控制項屬性與資料欄位之間的賦值方向(_exposure = double.Parse(txtExposure.Text) 是「畫面 → 資料」;txtGain.Text = _gain.ToString() 是「資料 → 畫面」)。

這些都是推測儲存對照、UI 對照與職責分群是依程式寫法推出來的線索。例如儲存鍵若是用變數組出來的字串、事件是用反射或框架設定的,就找不到。你那個 6 萬行的類別,分群可能合成一大群——可以把「樞紐門檻」調低,把共用很廣的欄位排除再看。每張表都可以篩選並匯出 CSV(含 BOM,Excel 直接開啟中文不會亂碼)。
延伸閱讀 ・John Ousterhout《A Philosophy of Software Design》第 2 版(Yaknyam Press,2021):談「深」的模組與複雜度從哪裡來,可和 God Class 的拆分互相對照。
・Fowler《Refactoring》收錄「Large Class」「Long Method」等壞味道與對應的手法(拆類別、搬移方法)。(附錄 B)

6.6　冤親債主

指令:debtors <類別>;網頁:God Class 頁的「冤親債主」分頁,以及類別圖頁右側欄的按鈕。

情境:接手一支沒人敢動的程式,裡面一堆成員沒有註解。想問問「這是誰寫的?最後是誰改的?」CodeAtlas 找出沒寫註解的成員(沒有前置註解、也沒有同行的尾端註解),對每個成員用 git log -L 追蹤「那幾行」的歷史,列出最後編輯者與上幾代編輯過的人。

用 -L 追蹤行範圍的好處是:不會被同一個檔案裡別人改了別的地方干擾。

要自己試,執行隨附的指令碼,它會在暫存資料夾建出有三位作者(Alice、Bob、Carol)歷史的 GodDemo:

powershell -ExecutionPolicy Bypass -File samples\GodDemo\建立git歷史.ps1
CodeAtlas.exe debtors "%TEMP%\GodDemo-git\GodDemo.sln" GodDemo.GodForm
{{snip:debtors}}

看 SaveSettings():最後是 Alice 改的,再前一代是 Carol,最早是 Bob。AddItem():最後 Carol,前一代 Alice。有註解的成員(如 _itemCount、Log)已被排除。

限制 ・找不到 git 時會明講,不會亂猜。
・「作者」取自 git 紀錄的作者欄,同一個人用不同名字或信箱會被當成不同人(CodeAtlas 沒有套用 .mailmap)。
・每個成員要跑一次 git log -L,成員很多時會慢,所以預設只查前 60 個。
・超過 2000 行的巨大類別,右側欄只看宣告處的歷史,成員請看各自的編輯者。
・這是「查事實」不是「找人算帳」——最後編輯者不等於寫壞的人。
延伸閱讀 Adam Tornhill《Your Code as a Crime Scene》第 2 版(Pragmatic Bookshelf,2024):用版本控制歷史分析程式碼的「熱點」與團隊如何影響架構。需要熟悉 git。(附錄 B)

7　類別圖與關係圖

網頁:/classes。左側是檔案大綱(可搜尋檔名、類別名或成員名),中間是圖,右側是符號資訊欄(點選類別後出現)。

7.1　三種檢視

  • 類別圖(含成員):每個類別一個方塊,分欄位、屬性、方法三區;
  • 關係圖(只顯示名稱):只顯示類別名稱,適合看整體結構;
  • Mermaid:產生 Mermaid 文字並繪製,可複製、下載 SVG,貼進文件或 wiki。

7.2　符號說明:三類關係

類別之間的關係分成四組,各自可以開關、各自設定層數。同一對類別只畫最強的一種:繼承 > 擁有 > 依賴。

組種類CodeAtlas 怎麼判斷
繼承繼承繼承自某個類別(介面繼承介面也算)。
實作實作某個介面。
擁有組合欄位或屬性是單一物件,且擁有者自己 new 出來(初始值或在自己的成員裡指派)。
聚合集合或陣列型別(List<X>、X[]),或是由建構子參數傳入的。
關聯其他持有關係(例如公開可寫的屬性)。
依賴—其餘的使用(方法參數、區域變數、呼叫、建立物件),且不屬於上面兩組。
巢狀—外層類別包含內層類別(外層 → 內層)。
這是啟發式判斷組合與聚合的區別在 C# 裡本來就看不出來(語言沒有這個概念),CodeAtlas 用「誰建立它」來推。例如由工廠方法回傳的物件會被判成「關聯」而不是「組合」。
延伸閱讀 類別圖各種線與菱形的正式意義,可查 Martin Fowler《UML Distilled》第 3 版(Addison-Wesley,2003;ISBN 0321193687),涵蓋 UML 2。(附錄 B)

7.3　不讓大類別爆圖

  • 每區只顯示前 N 項(預設 8),超過寫「… 另 k 項」。隱藏 private 可再縮短;
  • 拉遠自動只顯示名稱(縮放小於 0.45 倍);
  • 類別數超過上限(預設 150)時,只留關聯最多的,並提示你縮小範圍或指定焦點;
  • 在圖中尋找:輸入文字,符合的類別(含其成員)會亮起,其餘變淡;Enter 跳到第一個符合的。

7.4　子類別層數、巢狀類別、焦點

  • 焦點類別:輸入類別名稱,或在左側大綱點一下,或在圖上雙擊某個類別。只畫它與它周邊。
  • 各類關係的層數:繼承往上、往下各 N 層(所以子類別的子類別也畫得出來);擁有、依賴、巢狀也各自設層數。圖 7-1 設的是繼承 2 層。
  • 巢狀類別獨立成一個方塊,畫出它自己的成員,並用點線連到外層。

7.5　點選與資訊欄

點選一個類別:不相干的類別與線會變淡,只留它和直接相鄰的。右側同時顯示符號資訊:位置、說明(XML 註解的 summary)、類別度量(WMC、Ca、Ce)、最後編輯者與上幾代、沒寫註解的成員數與「查冤親債主」按鈕。

7.6　檔案大綱搜尋

左側大綱把類別依「所在檔案」分組。搜尋框同時比對檔名、類別名、成員名:搜 CalculateItem 會找到包含該方法的 Machine_CountItem_Parameters,並註明「含 CalculateItemParam」。點一個項目就把它設成焦點。

7.7　便利貼、存版面、下載 SVG

  • 便利貼:按「＋ 貼一張」,點兩下編輯(清空文字會刪除),旁邊色盤可換色(先選取便利貼再按顏色,或先選好顏色再新增)。重新產生圖時便利貼會保留。
  • 版面存取:「儲存」會把圖上每個類別的位置、便利貼、縮放,以及上方所有設定存成一個命名版面,存在你的 %AppData%\CodeAtlas\layouts;「載入」會原樣還原,不會重新排版。也可「匯出檔案 / 匯入檔案」(.json)給別人。
  • 下載 SVG:把目前畫面重新畫成向量圖。Mermaid 檢視則下載 Mermaid 繪出的 SVG。

8　函式流程與流程畫布

8.1　函式流程 /flow

選一個方法,產生五種圖。左邊搜尋選方法,上方可設「展開被呼叫方法幾層」、「顯示外部(.NET 框架)呼叫」。每張圖都有 Mermaid 與 PlantUML 兩種文字,圖的文字可以直接在右側編輯後重繪、插入敘述、複製、下載文字與 SVG。

8.1.1　循序圖

分支畫成 alt(沒有 else 的畫成 opt)、迴圈畫成 loop、switch 每個 case 一段、try/catch 畫成 critical。展開的被呼叫方法會畫出「回傳」箭頭。

CodeAtlas.exe flow samples\TestShop.sln Checkout.Run 1
{{snip:flow-seq}}

8.1.2　活動圖

Mermaid 沒有活動圖,所以 Mermaid 版用流程圖表示;PlantUML 版是真正的活動圖語法(start、if … endif、while、switch)。迴圈會回到判斷點,break、return 也處理了。

8.1.3　狀態圖(要勾選才產生)

找這個類別裡「列舉型別的欄位或屬性」被賦值的地方,依外圍的 if 與 switch 推出「從哪個狀態轉到哪個狀態、在哪個方法」。建構子或初始值給的是起始狀態。抓不到來源的標「任一狀態」。

8.1.4　資料流(要勾選才產生)

追蹤參數、區域變數、欄位、屬性之間的賦值,以及它們傳進哪些呼叫、哪些被回傳。梯形是參數,圓柱是欄位或屬性,圓角是區域變數,六角是呼叫,體育場形是回傳值;箭頭旁的 L 數字是行號。

狀態圖與資料流是推測所以要勾選才產生。資料流不處理別名、集合裡的內容、ref 的複雜情況;狀態圖只認「列舉欄位 + 賦值 + if/switch」這種寫法。

8.1.5　呼叫樹

往下追被呼叫的方法到指定層數,遇到循環標 [循環]。

8.2　流程畫布 /canvas

把好幾張流程放在同一張畫布上,手動拖拉整理、換色比較、合併、貼便利貼。左側上方點方法即可加入,下方是「畫布上的流程」清單。

排版規則

  • 每張流程由上往下排,分支也往下長;有分支就往外擴。
  • 迴圈的回頭線畫成側繞的虛線,不參與排版,所以迴圈佔的空間很小。
  • 你拖過的圖不會被自動排版動到。新加流程只排新的那一張,放在現有內容的右邊。按「重新排版(保留拖過的)」會略過你拖過的流程(清單上標 ✎);要全部重排得按「全部重新排版」並確認。
  • 拖整個外框是群組拖拉(裡面全部一起動),這不算「拖過」。也可以 Shift+拖曳框選多個節點,按「把選取的節點群組」自訂群組;選取群組外框後按「取消選取的群組」。

換色與合併

  • 每張流程有色盤,節點與外框一起換色,方便比較兩支程式。
  • 合併:勾選兩張以上,按「合併選取的流程」。勾選「相同敘述的節點合為一個」時,兩張流程裡文字相同的節點(例如「開始」「結束」或共同的步驟)會合成一個,連線改接過去。合併後會自動排版成新的一張。

便利貼、存版面、SVG

同第 7.7 節:便利貼可貼在畫布任何位置、點兩下編輯、換色;版面可儲存、載入、匯出、匯入;「下載 SVG」輸出向量圖。

PlantUML 還沒有實際繪製驗證CodeAtlas 離線版不內建 PlantUML,所以頁面對 PlantUML 只提供文字(可複製、下載),請貼到你有的 PlantUML 工具(例如 Visual Studio 的擴充或 plantuml.jar)。文字的語法我檢查過產出格式,但沒有用 PlantUML 程式實際繪製過(附錄 D)。

9　AI 問答:搭配 Copilot 使用

本章回答三個問題:Serena 是什麼?為什麼這個專案沒有直接用它?CodeAtlas 的「AI 上下文」怎麼讓 AI 讀得少、答得準,並且節省 token?

9.1　Serena MCP 是什麼(白話版)

先把三個名詞講清楚。

名詞白話說明
LSP
(Language Server Protocol)		編輯器和「懂某種語言的程式」之間的一套溝通規則。你在 Visual Studio Code 或其他編輯器裡按「跳到定義」「找所有參考」,背後常常就是編輯器問語言伺服器,語言伺服器回答「在第幾個檔案第幾行」。
MCP
(Model Context Protocol)		AI 應用程式(例如 Claude Code、Claude Desktop、Visual Studio Code、Cursor)和「外部工具」之間的一套溝通規則。工具用 MCP 向 AI 說「我能做這幾件事」,AI 需要時就來呼叫。
符號程式碼裡有名字的東西:類別、方法、欄位、屬性。「符號層級」的意思是:操作的單位是「這個方法」,而不是「第 120 到 140 行」或「這串文字」。

Serena(開源專案 oraios/serena)就是把這兩者接起來:它用語言伺服器(LSP)去理解程式碼,再包成 MCP 工具,交給 AI 使用。官方形容它是「給 AI 用的 IDE」:讓 AI 不必把整個檔案讀進來,也能「找到這個符號」「找出誰引用了它」「只改這個方法」。

它給 AI 哪些工具(依官方文件)

類別主要工具做什麼
符號工具find_symbol、get_symbols_overview、find_referencing_symbols、find_declaration、find_implementations找符號、列出檔案的大綱、找誰引用了它、找定義與實作
replace_symbol_body、insert_after_symbol、insert_before_symbol、rename_symbol、safe_delete_symbol以符號為單位改寫、插入、跨檔改名、刪除
檔案工具read_file、list_dir、find_file、search_for_pattern、replace_content 等一般的檔案讀取與搜尋(在 Claude Code 這類環境裡,官方說通常預設停用)
記憶工具write_memory、read_memory、list_memories 等把專案筆記存下來,下次任務再讀
其他execute_shell_command、activate_project、onboarding 等執行指令、切換專案、第一次認識專案

官方文件說多數設定只會啟用其中一部分,標示 optional 的預設不啟用。完整且最新的清單請以官方文件為準(附錄 B 列出網址)。

它怎麼跑

  • 官方說 uv(一個 Python 套件管理工具)是唯一必要的前置安裝;快速開始的指令是 uv tool install -p 3.13 serena-agent 然後 serena init。
  • 有兩種後端:預設是語言伺服器(LSP),免費開源;另一個是付費的 JetBrains 外掛。
  • 支援的語言官方文件寫「超過 40 種」,包含 C#。
  • 官方也提醒:不要透過 MCP 或外掛市集安裝 Serena。
  • 授權:Serena 本體是 GPL-3.0-or-later,其中的 SolidLSP 部分是 MIT;合在一起散布時整體適用 GPL(依官方 README)。
一句話Serena = 「語言伺服器」+「MCP 包裝」。AI 靠它用「符號」而不是「整個檔案」來看程式,所以讀得少、改得準。

9.2　Roslyn 與 Serena 的關係

Roslyn 是微軟的 C# 編譯器平台:它把 C# 原始碼解析成語法樹,並提供「語意模型」——知道每個名字指的是哪個符號、型別是什麼。Visual Studio 裡的 C# 智慧提示、跳到定義、找所有參考,底層都靠它。

關係是:Serena 處理 C# 時,底層用的就是以 Roslyn 為基礎的 C# 語言伺服器(官方語言支援頁寫:C# 預設使用「Roslyn language server」,語言代號 csharp;也可改用 OmniSharp)。換句話說,「Roslyn 負責看懂 C#,LSP 負責把答案傳出來,MCP 負責讓 AI 來問」。

CodeAtlas 做的就是:跳過 LSP 與 MCP 那兩層,直接用 Roslyn 的程式介面(Microsoft.CodeAnalysis)做同樣類型的查詢——找符號、找參考、呼叫關係——而且是在 .NET Framework 4.8 上跑。

9.3　為什麼 Serena 不能直接和離線版結合

以下每一點都是依 Serena 官方文件所寫的需求,對照你的環境(離線、不能安裝、只有 .NET 4.8、Visual Studio 與 Copilot):

#Serena 的需求(官方文件)你的環境結果
1必須先安裝 uv(唯一必要的前置條件),並以它安裝 Serena。不能安裝任何東西。衝突
2C# 的語言伺服器需要 .NET v10 以上(Windows 上還需要 PowerShell 7 以上)。只保證有 .NET Framework 4.8。衝突
3許多語言伺服器的相依檔案「在第一次啟用該語言專案時下載」。官方有提供受限網路的做法(事先下載),但沒有說明 C# 是否需要。完全離線。不確定,風險高
4Serena 是一個 MCP 伺服器,需要一個支援 MCP 的 AI 用戶端來連它。用 Copilot。你們的 Visual Studio / Copilot 版本是否能設定 MCP 伺服器,我沒有驗證。未驗證
5授權:本體 GPL-3.0-or-later,合併散布時整體適用 GPL。要把它隨公司工具散布。需要法務評估
6官方文件沒有說明是否能完全離線運作。必須離線。未說明

所以結論不是「Serena 不好」,而是:在「離線、不能安裝、只有 .NET 4.8」這組限制下,它的前置需求(第 1、2 點)直接做不到。CodeAtlas 是為這組限制量身做的替代:一個資料夾、拖進去就能跑。

如果你的環境之後放寬例如允許安裝 uv 與 .NET 10、能連網下載語言伺服器、Copilot 能接 MCP,那麼 Serena 與 CodeAtlas 並不衝突:Serena 擅長讓 AI「自己動手查、改」,CodeAtlas 擅長讓「人」看圖、看度量、看歷史。兩者可以並用。

9.4　CodeAtlas 的 AI 上下文

Copilot 沒辦法直接呼叫 CodeAtlas(第 9.3 節第 4 點),所以做法是:你用 CodeAtlas 產生一段短文字,貼給 Copilot(貼進對話,或存成檔案附加)。這段文字就叫 AI 上下文。設計上有三個重點:

  1. 只給簽章與位置,不給內文。每個成員一行:修飾詞、型別、名稱、參數、所在檔案與行號範圍,以及它的 CC。
  2. 大類別自動截斷。成員預設最多列 40 個,超過寫「另有 k 個成員未列出」,並提示改指定「類別.成員」取得個別上下文。
  3. 需要內文時,由 AI(或你)指定目標再讀。用 body 指令只讀那一個方法,還可以再指定行號範圍,只讀方法裡的一段。

你的類別都很大,所以這樣設計:摘要要短,細節按需讀取。

CodeAtlas.exe context 方案.sln 類別名稱          <- 類別的摘要
CodeAtlas.exe context 方案.sln 類別名稱.方法名稱  <- 單一方法的摘要(含誰呼叫它、它呼叫誰)
CodeAtlas.exe body    方案.sln 類別名稱.方法名稱  <- 讀整個方法的內文

9.7　正例與反例

正例:先摘要,再按需讀
  1. 貼類別摘要(約 1~2 千字元);
  2. AI 或你指定「想看哪個方法」;
  3. 用 body 只讀該方法,太長就再縮成行號範圍。
總量:摘要 + 一小段內文。每多問一個問題,只增加一小段。
反例:整份貼上
  1. 把整個 .cs 檔或整個類別貼進對話;
  2. 對話裡其他問題也一直帶著這份內容;
  3. 類別很大時超過 AI 一次能讀的長度,被截斷或忽略。
總量:每個問題都帶整份(上表:5~20 倍的字元)。
什麼時候摘要「不」划算 ・方法很短(如 References),直接給內文就好;
・你問的問題本來就需要看整個類別的每一行(例如「逐行 code review」),摘要幫不上忙;
・類別很小,摘要和原始碼差不多大。
這些情況用 body 直接取內文,不要硬套摘要流程。

10　限制與疑難排解

10.1　已知限制

  • 只在小型測試專案上驗證過。你的大型專案(尤其約 6 萬行的類別)的速度、記憶體、可讀性都沒量過。圖太大時,請用焦點與層數縮小範圍。
  • 語意分析抓不到反射、依賴注入、字串型的類別或方法名稱、事件在設定檔裡的掛接。
  • 泛型、擴充方法、partial、dynamic 等複雜情況,我只做了基本處理與有限測試。
  • MI 是近似值;死碼的「低」可信度是提醒不是結論。
  • 儲存對照、UI 對照、職責分群、狀態圖、資料流、組合與聚合的判斷,都是依寫法的推測。
